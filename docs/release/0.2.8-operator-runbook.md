# OpenCodex Desktop 0.2.8 Operator Runbook

Date: 2026-06-10

## Purpose

This runbook is the operator checklist for the DeepSeek GUI `v0.2.8` ingestion
lane. It starts after local Wave 5-7 evidence exists and before any public beta
or release mutation.

Do not create tags, GitHub releases, R2 uploads, update-channel promotions, or
public release notes until the publish authorization step is explicitly
approved in the current thread.

## Non-Secret Readiness Check

Run:

```bash
npm run release:readiness -- --json
```

Expected before operator proof:

```text
status: blocked
```

Expected package artifact status:

```text
dist/mac-arm64/OpenCodex Desktop.app/Contents/MacOS/OpenCodex Desktop present
dist/mac-arm64/OpenCodex Desktop.app/Contents/Resources/app.asar present
unpacked Kun runtime dependencies present
```

The command prints key names and presence booleans only. It must not print
secret values.

## Baseline Verification

Use these commands before any release mutation:

```bash
git fetch upstream --tags --prune
git describe --tags --always upstream/master
git rev-parse --short upstream/master
git rev-parse --short upstream/develop
git rev-list --left-right --count upstream/master...upstream/develop
npm run typecheck
npm test
npm --prefix kun run typecheck
npm --prefix kun test
npm run smoke:release
git diff --check
```

Expected upstream baseline for this lane:

```text
upstream/master: v0.2.8 / f1f8d1b
upstream/develop: e7e8252
branch relationship: 12 17
```

If upstream moves, update the wave ledger before continuing.

## macOS Signing Choice

Choose one path.

### Signed And Notarized

Verify local Apple credentials before building:

```bash
npm run verify:apple -- \
  --p12 /path/to/developer-id.p12 \
  --p12-password "$P12_PASSWORD" \
  --p8 /path/to/AuthKey_KEYID.p8 \
  --key-id "$APPLE_API_KEY_ID" \
  --issuer "$APPLE_API_ISSUER"
```

Optional online notary credential check:

```bash
npm run verify:apple -- \
  --p12 /path/to/developer-id.p12 \
  --p12-password "$P12_PASSWORD" \
  --p8 /path/to/AuthKey_KEYID.p8 \
  --key-id "$APPLE_API_KEY_ID" \
  --issuer "$APPLE_API_ISSUER" \
  --check-notary
```

Only after this proof exists, set:

```bash
OPENCODEX_RELEASE_MAC_SIGNING_DECISION=signed-notarized
```

### Unsigned Local Beta

Use this only if the release is explicitly scoped as a local beta and release
notes say macOS Gatekeeper will block first launch.

Only after that decision is approved, set:

```bash
OPENCODEX_RELEASE_MAC_SIGNING_DECISION=unsigned-local-beta
```

## Manual Packaged-App Smoke

Use the packaged app, not only the dev server.

Record:

```text
Date:
Operator:
macOS version:
Architecture:
App artifact path:
Signing choice:
```

Smoke checklist:

- First run opens without a crash.
- Settings opens.
- Settings -> Agents shows only Kun as the live runtime.
- Provider settings can be inspected without leaking secrets.
- Chat can create a Kun thread.
- Chat can stream a reply.
- Tool approval and denial still work.
- Interrupting a turn still works.
- Changed-file review card appears when file-changing tool output is present.
- Locale can switch to English.
- Locale can switch to Chinese.
- Locale can switch to Arabic and document direction becomes RTL.
- App restart preserves expected settings.
- Packaged app launches again after restart.

Only after this proof exists, set:

```bash
OPENCODEX_RELEASE_MANUAL_PACKAGED_SMOKE=1
```

## Update And Rollback Notes

Channel:

```text
frontier or stable:
```

Update notes:

- Release channel must match `RELEASE_CHANNEL`.
- macOS artifacts must match the chosen signing scope.
- R2 latest promotion is separate from artifact upload.
- GitHub release should remain draft until all platform assets are present.

Rollback notes:

- If R2 latest promotion fails before latest metadata is changed, do not retry
  blindly; inspect uploaded object keys first.
- If latest metadata is promoted incorrectly, promote the previous known-good
  tag back to the same channel.
- If GitHub release assets are incomplete, keep the release draft and re-upload
  missing assets with `gh release upload --clobber`.
- If signed macOS launch fails, do not promote; rebuild after Apple credential
  verification and repeat manual packaged-app smoke.
- If live-provider smoke fails, do not claim provider readiness in release
  notes; either fix and rerun or scope the beta notes down.

Only after the release channel and rollback path are reviewed, set:

```bash
OPENCODEX_RELEASE_UPDATE_ROLLBACK_NOTES=1
```

## Publish Authorization

Do not set publish authorization until the operator explicitly approves release
mutation in the current thread.

Only after approval, set:

```bash
OPENCODEX_RELEASE_OPERATOR_APPROVED=1
OPENCODEX_RELEASE_PUBLISH_AUTHORIZED=1
```

Then rerun:

```bash
npm run release:readiness -- --strict
```

`--strict` must pass before running release scripts.

## Mutating Release Commands

These are intentionally last.

macOS draft release:

```bash
./scripts/release-mac.sh --channel frontier
```

macOS draft release plus R2 upload and latest promotion:

```bash
./scripts/release-mac.sh --channel frontier --r2
```

Windows continuation after macOS draft:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/release-win.ps1 \
  --tag vX.Y.Z \
  --channel frontier
```

Do not use `--publish` until all platform assets and update metadata are
verified.
